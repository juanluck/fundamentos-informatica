2  Tema 1 · Introducción a los computadores

Prototipo pedagógico

¿Qué ocurre realmente desde que pulsamos una tecla, abrimos una aplicación o reproducimos un vídeo hasta que el computador nos devuelve un resultado?

Este tema construye una primera respuesta. No intentaremos conocer todavía todos los detalles de un computador. Empezaremos por una idea muy sencilla —procesar información— e iremos abriendo la caja poco a poco.

Objetivos

Al finalizar el tema deberías poder:

  • explicar qué entendemos por computador, dato e información;
  • razonar por qué los computadores utilizan representaciones binarias;
  • relacionar número de bits y número de combinaciones posibles;
  • reconocer las principales unidades funcionales de un computador;
  • distinguir el papel del bus de datos y del bus de direcciones;
  • describir de forma intuitiva cómo se ejecuta un programa;
  • interpretar magnitudes básicas de prestaciones;
  • reconocer que distintos computadores responden a necesidades diferentes;
  • distinguir las principales capas y categorías de software.

2.1 ¿Qué es un computador?

Antes de hablar de procesadores, memoria o programas conviene responder una pregunta más básica: ¿qué hace un computador?

Podemos observarlo como una caja que recibe datos, realiza algún procesamiento y produce un resultado.

Cuando escribes una palabra, el teclado proporciona datos de entrada. Cuando una aplicación calcula una ruta, procesa datos. Cuando la pantalla muestra el mapa, estás viendo el resultado de ese procesamiento.

Concepto clave

La informática estudia el tratamiento automático de la información mediante sistemas capaces de representar, almacenar y procesar datos.

Un computador es una máquina programable que procesa información representada de una forma que puede manipular físicamente.

2.1.1 Datos e información

Los términos dato e información están relacionados, pero no son idénticos.

Un dato es una representación: un número, un símbolo, una medida o una secuencia de caracteres. Adquiere significado cuando sabemos cómo interpretarlo.

Ejemplo

El valor 23 por sí solo es un dato. Puede representar una temperatura, una edad, una dirección de memoria o el número de estudiantes de un grupo. El significado depende del contexto y de las reglas de interpretación.

Esta idea será importante durante todo el curso: el mismo patrón físico puede significar cosas diferentes dependiendo de cómo decidamos interpretarlo.

2.1.2 Hardware y software

Para que un computador resulte útil necesitamos dos dimensiones inseparables:

  • hardware: los componentes físicos;
  • software: las instrucciones y programas que determinan qué debe hacer el hardware.

Todavía no necesitamos conocer sus detalles. De momento basta con recordar que el hardware proporciona capacidad de procesamiento y el software la dirige hacia una tarea concreta.

Ejercicio 1.1 ● Básico

Entrada, procesamiento y salida

Para cada situación, identifica qué podría considerarse entrada, qué procesamiento se realiza y cuál es la salida:

  1. una calculadora suma dos números;
  2. una cámara de móvil realiza una fotografía;
  3. una aplicación de navegación calcula una ruta.

Solución

No existe una única redacción válida. Lo importante es distinguir las tres funciones.

En una calculadora, por ejemplo, los números y la operación son la entrada; la suma es el procesamiento; el resultado mostrado es la salida.

2.2 ¿Cómo representa la información?

Un computador debe representar físicamente números, letras, imágenes, sonido e instrucciones. Para hacerlo resulta muy útil trabajar con sistemas que puedan distinguir de forma fiable dos estados.

Esos estados pueden implementarse de muchas maneras: dos niveles eléctricos, dos orientaciones magnéticas, presencia o ausencia de carga, etc. Los símbolos 0 y 1 nos permiten nombrarlos de forma cómoda.

Importante

En este contexto inicial, 0 y 1 no deben entenderse únicamente como números. También pueden verse como dos símbolos que representan dos estados distinguibles.

2.2.1 El bit

Llamamos bit a una unidad que puede tomar uno de dos valores posibles.

Con un solo bit tenemos dos combinaciones:

0
1

Con dos bits aparecen cuatro:

00
01
10
11

Y con tres bits:

000  001  010  011
100  101  110  111

El patrón es sencillo:

Bits Combinaciones posibles
1 2
2 4
3 8
4 16

Después de observar estos casos podemos formalizar la relación:

\[ n\text{ bits} \longrightarrow 2^n\text{ combinaciones} \]

Concepto clave

Con \(n\) bits pueden construirse \(2^n\) patrones distintos. Los patrones no tienen significado por sí solos: somos nosotros quienes establecemos qué representa cada uno.

2.2.2 De combinaciones a códigos

Supongamos que solo queremos representar cuatro letras. Podemos acordar el siguiente código:

Patrón Símbolo
00 A
01 B
10 C
11 D

Nada obliga a utilizar exactamente esa correspondencia. Lo importante es que emisor y receptor compartan el mismo código.

Ejercicio 1.2 ● Básico

¿Cuántos bits necesito?

¿Cuántos bits hacen falta como mínimo para disponer de un patrón diferente para cada uno de los diez dígitos decimales (0 a 9)?

Solución

Con 3 bits solo disponemos de \(2^3=8\) combinaciones, por lo que no es suficiente.

Con 4 bits disponemos de \(2^4=16\) combinaciones. Por tanto, el mínimo es 4 bits.

La pregunta inversa aparece constantemente en informática. Si necesitamos representar \(N\) posibilidades, buscamos el menor \(n\) tal que:

\[ 2^n \ge N \]

que puede expresarse como:

\[ n=\lceil\log_2 N\rceil \]

El logaritmo en base 2 aparece así como respuesta a una pregunta concreta: ¿cuántos bits necesito?

2.2.3 Del bit al byte

Trabajar bit a bit sería incómodo. Por convenio, agrupamos habitualmente ocho bits en una unidad llamada byte.

\[ 1\ \text{byte}=8\ \text{bits} \]

A partir del byte expresamos capacidades mayores. Conviene distinguir entre prefijos decimales y binarios:

Unidad Valor
kB \(10^3\) bytes
MB \(10^6\) bytes
GB \(10^9\) bytes
KiB \(2^{10}\) bytes
MiB \(2^{20}\) bytes
GiB \(2^{30}\) bytes

Ejemplo

Una conexión de 100 Mb/s expresa una velocidad en megabits por segundo. Un archivo de 1 GB expresa un tamaño en gigabytes. Antes de calcular un tiempo de descarga debemos llevar ambas magnitudes a unidades compatibles.

Ejercicio 1.3 ●● Intermedio

Tiempo de descarga

Ignorando pérdidas y sobrecargas, ¿cuánto tardaría en descargarse un archivo de 1 GB a través de una conexión de 100 Mb/s? Utiliza unidades decimales en ambas magnitudes.

Solución

\(1\ \text{GB}=8\ \text{Gb}=8000\ \text{Mb}\).

Entonces:

\[ t=\frac{8000\ \text{Mb}}{100\ \text{Mb/s}}=80\ \text{s} \]

En condiciones ideales, tardaría aproximadamente 80 segundos.

Para saber más

La conocida historia del tablero de ajedrez y los granos de trigo es una forma intuitiva de visualizar cómo crecen las potencias de 2. En una versión posterior de este capítulo puede convertirse en una visualización interactiva.

2.3 ¿Qué hay dentro de un computador?

Ya sabemos que un computador recibe datos, los representa y los procesa. Ahora podemos abrir la caja.

En un primer modelo bastan tres grandes grupos:

  • procesador (CPU): ejecuta operaciones e instrucciones;
  • memoria: conserva temporalmente datos e instrucciones que están siendo utilizados;
  • entrada/salida (E/S): comunica el computador con otros dispositivos y con el exterior.

Este esquema es deliberadamente simple. Más adelante estudiaremos arquitecturas y jerarquías de memoria con mayor precisión.

2.3.1 El procesador

Dentro de la CPU podemos distinguir, de forma conceptual:

  • una unidad de control, que coordina la ejecución de instrucciones;
  • una unidad aritmético-lógica (ALU), que realiza operaciones aritméticas y lógicas;
  • registros, pequeñas unidades de almacenamiento muy cercanas a las unidades de ejecución.

2.3.2 La memoria

La memoria principal puede imaginarse inicialmente como una secuencia de posiciones. Cada posición almacena un patrón de bits y tiene una forma de ser identificada.

Posición Contenido
0 10110101
1 01101011
2 11100010
… …

Concepto clave

En la memoria se almacenan datos e instrucciones. Para el hardware, ambos son patrones de bits; su interpretación depende de cómo se utilicen.

2.3.3 Palabra y registros

Los computadores suelen manipular grupos de bits de un tamaño determinado. El concepto de palabra permite hablar de esa unidad natural de procesamiento. Encontraremos arquitecturas de 8, 16, 32 o 64 bits, aunque el significado exacto de esas etiquetas requiere más contexto del que necesitamos ahora.

Ejercicio 1.4 ● Básico

Reconocer funciones

Relaciona cada elemento con su función principal: CPU, memoria, dispositivo de entrada/salida.

  1. conservar temporalmente datos e instrucciones;
  2. ejecutar instrucciones;
  3. comunicar el sistema con el exterior.

Solución

  1. memoria;
  2. CPU;
  3. entrada/salida.

2.4 ¿Cómo se comunican sus componentes?

Tenemos procesador y memoria. Ahora surge una necesidad concreta: ¿cómo intercambian información?

Supongamos que la CPU quiere leer la posición 2 de la memoria. Hay dos problemas diferentes:

  1. indicar qué posición desea;
  2. transferir el contenido de esa posición.

Esta distinción conduce a dos mecanismos diferentes.

2.4.1 Bus de direcciones: ¿dónde?

El procesador necesita expresar una dirección. Si dispone de \(n\) bits para hacerlo, puede generar hasta \(2^n\) patrones diferentes y, por tanto, distinguir hasta \(2^n\) direcciones.

Aquí reaparece exactamente la misma idea matemática que usamos para contar códigos.

Ejemplo

Con un bus de direcciones de 4 bits pueden generarse \(2^4=16\) patrones distintos, desde 0000 hasta 1111.

2.4.2 Bus de datos: ¿qué contenido?

Una vez seleccionada la posición, necesitamos transportar el contenido. El bus de datos proporciona el camino por el que circulan esos bits entre los componentes.

Concepto clave

El bus de direcciones identifica una posición o destino. El bus de datos transporta la información que se intercambia.

Ejercicio 1.5 ● Básico

Direcciones posibles

Una memoria utiliza un bus de direcciones de 10 bits. ¿Cuántas direcciones distintas pueden generarse?

Solución

\[2^{10}=1024\]

Pueden generarse 1024 direcciones diferentes.

Ejercicio 1.6 ●●● Avanzado

Dimensionar buses

Considera un computador organizado en palabras de 32 bits y con una memoria de 32 MiB, direccionada por palabras.

  1. ¿Cuántos bits debería transportar como mínimo el bus de datos para mover una palabra completa?
  2. ¿Cuántas palabras contiene la memoria?
  3. ¿Cuántos bits necesita el bus de direcciones?

Solución

Una palabra contiene 32 bits, por lo que un bus capaz de transportar una palabra completa en una transferencia tendrá 32 bits.

\(32\ \text{MiB}=2^{25}\) bytes. Cada palabra ocupa 4 bytes, de modo que:

\[ \frac{2^{25}}{2^2}=2^{23}\ \text{palabras} \]

Para identificar \(2^{23}\) palabras hacen falta 23 bits de dirección.

2.5 ¿Cómo ejecuta un programa?

Hasta ahora sabemos dónde pueden estar los datos y quién los procesa. Falta unir hardware y software.

Un programa puede verse, en primera aproximación, como una secuencia de instrucciones. Para ejecutarlo, sus instrucciones y los datos necesarios deben estar accesibles para el procesador.

Podemos describir intuitivamente el proceso mediante un ciclo:

Más adelante estudiaremos este ciclo con detalle. Por ahora nos interesa que proporciona una explicación sencilla de por qué conceptos como reloj, instrucciones o CPI afectan al tiempo de ejecución.

2.5.1 El reloj y la frecuencia

Muchos procesadores coordinan su actividad mediante una señal periódica de reloj. La frecuencia indica cuántos ciclos de reloj se producen por segundo.

\[ 1\ \text{GHz}=10^9\ \text{ciclos/s} \]

Pero frecuencia no significa directamente «instrucciones por segundo»: una instrucción puede requerir, en promedio, más de un ciclo.

2.5.2 CPI y tiempo de CPU

El CPI (cycles per instruction) expresa el número medio de ciclos de reloj utilizados por instrucción en un determinado contexto.

Una relación básica es:

\[ T_{CPU}=N_{instr}\times CPI\times T_{ciclo} \]

Como \(T_{ciclo}=1/f\), también podemos escribir:

\[ T_{CPU}=\frac{N_{instr}\times CPI}{f} \]

Importante

Una frecuencia de reloj mayor no garantiza por sí sola que un computador ejecute un programa más rápido. El tiempo depende también del número de instrucciones, del CPI y de muchos otros factores que estudiaremos más adelante.

2.5.3 MIPS y FLOPS

Dos métricas que aparecen con frecuencia son:

  • MIPS: millones de instrucciones por segundo;
  • FLOPS: operaciones de coma flotante por segundo.

Miden aspectos diferentes y su utilidad depende del tipo de carga de trabajo.

Ejercicio 1.7 ●● Intermedio

Tiempo de ejecución

Un programa ejecuta \(5\times10^8\) instrucciones en un procesador de 2 GHz con un CPI medio de 2. ¿Cuál sería su tiempo de CPU según este modelo simplificado?

Solución

\[ T_{CPU}=\frac{5\times10^8\times2}{2\times10^9}=0.5\ \text{s} \]

El tiempo resultante es 0,5 segundos.

2.6 ¿Todos los computadores son iguales?

Un portátil, un teléfono, la centralita de un automóvil, un servidor y un supercomputador comparten ideas fundamentales, pero están diseñados bajo restricciones muy diferentes.

No existe una única clasificación perfecta. Resulta más útil observar qué problema debe resolver cada sistema.

Sistema Prioridades habituales
sistema empotrado consumo, coste, tamaño, respuesta específica
dispositivo móvil consumo, integración, prestaciones, autonomía
computador personal flexibilidad y propósito general
servidor capacidad, disponibilidad, concurrencia
supercomputador rendimiento masivo y paralelismo

2.6.1 Propósito general y propósito específico

Un computador personal debe poder ejecutar una gran diversidad de aplicaciones. En cambio, un controlador integrado en un electrodoméstico puede estar diseñado para una tarea muy concreta.

2.6.2 CPU y MCU

En sistemas empotrados es frecuente utilizar un microcontrolador (MCU), que integra en un mismo dispositivo procesador, memoria y periféricos destinados al control de sistemas específicos.

Ejercicio 1.8 ●● Intermedio

Comparar necesidades

Compara un reloj inteligente y un servidor de un centro de datos. Propón al menos tres prioridades de diseño que sean diferentes entre ambos.

Solución

Una respuesta razonable podría destacar autonomía, tamaño y consumo como prioridades críticas del reloj, mientras que en el servidor pesan especialmente capacidad de procesamiento, memoria, almacenamiento, disponibilidad y servicio concurrente a muchos usuarios.

2.7 ¿Qué papel juega el software?

El hardware proporciona recursos. El software organiza esos recursos y los utiliza para resolver problemas.

Una representación simplificada por capas es:

2.7.1 Software de sistema

El sistema operativo administra recursos del computador y proporciona servicios sobre los que se apoyan las aplicaciones. Los controladores permiten gestionar dispositivos concretos y el firmware contiene software estrechamente ligado al hardware.

2.7.2 Aplicaciones

Las aplicaciones utilizan las capacidades del sistema para realizar tareas útiles: comunicación, edición, cálculo, diseño, navegación, reproducción multimedia, etc.

2.7.3 Lenguajes y traducción

Los programadores suelen expresar soluciones mediante lenguajes comprensibles para las personas. Esas descripciones deben transformarse o interpretarse para que el computador pueda ejecutar las instrucciones correspondientes.

2.7.4 Software como herramienta de ingeniería

Para un ingeniero, el computador no es solo un objeto de estudio. Es también una herramienta de trabajo. Podemos organizar el software por la función que cumple:

  • cálculo numérico y científico;
  • simulación y modelado;
  • diseño;
  • programación y automatización;
  • tratamiento y visualización de datos;
  • documentación técnica;
  • colaboración y control de versiones.

Los productos concretos cambiarán con el tiempo; estas funciones son más estables.

Tarea 1.9 ●● Intermedio

Tu mapa de herramientas

Elige tres herramientas software que hayas utilizado o que conozcas. Para cada una, indica qué problema resuelve, qué tipo de usuario la emplea y en cuál de las categorías anteriores la situarías.

Solución

La respuesta es abierta. Debe justificarse la función de cada herramienta, no limitarse a enumerar nombres de programas.

3 Cierre · Del clic al resultado

Volvamos a la pregunta inicial. Haces clic sobre el icono de una aplicación. ¿Qué ocurre?

Aún no conocemos todos los detalles, pero ya podemos construir una historia coherente:

El clic llega como entrada. El software participa en la gestión de la acción. El programa y sus datos se encuentran en memoria o deben hacerse accesibles al procesador. La CPU ejecuta instrucciones, intercambia datos con memoria y dispositivos y, finalmente, obtenemos una salida.

Los próximos temas irán abriendo cada una de estas cajas.

Resumen

  • Un computador procesa información representada mediante datos.
  • Los bits permiten construir patrones binarios; con \(n\) bits existen \(2^n\) combinaciones.
  • CPU, memoria y entrada/salida forman un primer modelo funcional del computador.
  • Direcciones y datos responden a problemas diferentes y se comunican mediante mecanismos distintos.
  • Un programa puede entenderse inicialmente como una secuencia de instrucciones ejecutadas por la CPU.
  • Frecuencia, CPI, instrucciones y tiempo de ejecución están relacionados, pero ninguna métrica aislada explica todo el rendimiento.
  • Los computadores adoptan formas distintas porque responden a requisitos diferentes.
  • El software convierte los recursos físicos en herramientas capaces de resolver tareas.

3.1 Problemas integradores

Ejercicio 1.10 ●●● Avanzado

Del código a la memoria

Un sistema necesita representar 200 símbolos distintos y almacenar 1024 palabras diferentes de memoria.

  1. ¿Cuántos bits hacen falta como mínimo para codificar cada símbolo?
  2. ¿Cuántos bits hacen falta para seleccionar una de las 1024 palabras?
  3. Explica por qué ambos cálculos utilizan la misma idea matemática aunque resuelvan problemas diferentes.

Solución

Para 200 símbolos necesitamos el menor \(n\) tal que \(2^n\ge200\). Como \(2^7=128\) y \(2^8=256\), hacen falta 8 bits.

Para 1024 palabras, \(1024=2^{10}\), por lo que hacen falta 10 bits de dirección.

En ambos casos contamos cuántos patrones diferentes pueden construirse con \(n\) bits. Lo que cambia es la interpretación: en el primer caso cada patrón representa un símbolo; en el segundo, una posición de memoria.
